# Telegram-администрирование после Phase 8

Вход: `/admin` в личном чате. Доступ только для `ADMIN_TELEGRAM_IDS`.
Все основные действия выполняются кнопками и обычными текстовыми ответами. JSON не требуется.
Пользовательский ввод денежных сумм — **рубли** с максимум двумя знаками после запятой.
В БД по-прежнему сохраняются целые копейки. Проценты в формах вводятся как `20` или `12,5`.

## Серверы

`/admin → VPN-серверы → Добавить`:

1. Название.
2. Страна.
3. Публичный hostname/IP, без `https://` и порта.
4. Порт, 1–65535 (по умолчанию 443).
5. Inbound ID (для mock можно пропустить).
6. Максимум клиентов (можно пропустить).
7. Приоритет: меньшее число выбирается первым.
8. Предпросмотр → **Сохранить**.

Провайдер определяется `VLESS_PROVIDER`. Выбор 3x-ui в runtime пока отклоняется: адаптер не реализован.
В карточке: страна, включённость, число занятых мест / лимит, приоритет, hostname/port.
Кнопки: включить/выключить, редактировать, удалить, назад. Toggle/delete требуют подтверждения.
В счёт лимита входят все неудалённые конфигурации, включая отключённые и ожидающие.
`active=false` запрещает новые конфигурации, не обрывая оплаченные существующие.

Изменение host, port, provider или inbound запрещено для сервера с историей конфигураций.
Удаление разрешено только без истории; иначе выключите сервер. При одновременном редактировании
сохранение устаревшей версии отклоняется — откройте карточку заново.

## Тарифы

`Тарифы → Добавить`: название → **Посуточный** или **Пакет дней** → цена / длительность → предпросмотр.
В пакете задаются дни и цена пакета, в PAYG только цена суток. Например `6,66`, `199` за 30 дней.
Есть карточка, редактирование и включение/выключение.
Цена и длительность фиксируются в конфигурации при создании; изменения тарифов касаются новых конфигураций.

## Каналы-спонсоры

`Каналы → Добавить`: название → отрицательный числовой chat ID → ссылка `https://t.me/...` → предпросмотр.
Бот должен быть администратором канала. Для приватного канала укажите действующий invite URL.
Ошибка проверки не открывает доступ. При потере прав исправьте их или выключите канал в карточке.

## Промокоды

Код → бонус в рублях → общий лимит → лимит на пользователя → начало → конец → предпросмотр.
Код: латинские буквы, цифры, `_`, `-`; регистр нормализуется. Тип MVP — бонус на баланс.
Даты: `ДД.ММ.ГГГГ ЧЧ:ММ`, **UTC**. Начало можно пропустить для «сейчас», конец — для бессрочного кода.
Номинал использованного кода не меняется; общий лимит нельзя снизить ниже числа активаций.
Пользователям разрешено максимум пять попыток ввода за минуту в одном процессе.

## Рефералы, бонусы, общие настройки

`Настройки` открывают три пошаговых формы:

- **Реферальная программа:** включение, бонус приглашённому, бонус пригласившему,
  процент от реальных оплаченных пополнений, минимальный вывод.
- **Бонус пополнения:** включение, порог суммы, процент.
- **Общие настройки:** username поддержки, информация, preset-суммы через пробел, maintenance.

Пустую поддержку можно пропустить. В bonus-полях ноль выключает фиксированное начисление.
Первичная referral attribution сохраняется навсегда даже при выключенных бонусах.
Настройки применяются на момент соответствующей операции, не задним числом.
Если другой администратор изменил те же настройки во время ввода, откройте форму заново.

## Пользователи и баланс

Поиск: Telegram ID, `@username` или `#внутренний_ID`. В карточке оба кошелька,
активные VPN, referrer, статус и дата регистрации. Имя обновляется из Telegram updates.
Для начисления/списания: внутренний ID → сумма **в рублях** (`-100` для списания) → комментарий → подтверждение.
Комментарий обязателен. Отрицательный итоговый баланс запрещён. Повторное подтверждение не дублирует проводку.
Блокировка ставит отключение существующих VPN в очередь; разблокировка автоматически их не включает.

## Платежи

В списке нажмите платёж, чтобы проверить его через API. Одно событие может дать
основное зачисление, бонус и реферальное вознаграждение; каждое имеет отдельную проводку.
**Восстановить неопределённый счёт:** внутренний payment ID → внешний invoice ID из Crypto Pay → подтверждение.
Сервис проверяет payload, RUB и сумму. Ручного переключателя «считать оплаченным» нет.
Не создавайте заменяющий invoice до проверки старого после timeout.

## Выводы

Откройте заявку, проверьте сумму и расшифрованные реквизиты:

- `PENDING → APPROVED` — одобрить.
- `APPROVED → PAID` — отметить выплаченной **после фактической ручной выплаты**.
- `PENDING/APPROVED → REJECTED` — отклонить с однократным возвратом резерва.

Изменение подтверждается отдельной кнопкой. Завершённые заявки не переоткрываются.
Реквизиты требуют исходного `ENCRYPTION_KEY`; его потерю нельзя исправить новым случайным ключом.

## Навигация и отладочные формы

В формах есть **Назад**, **Отмена**, а `/cancel` отменяет любой ввод. `/start` и `/admin`
сбрасывают предыдущий сценарий. Каждая показанная admin-клавиатура имеет одноразовый nonce;
старые кнопки отклоняются. При перезапуске незавершённые формы сбрасываются.

Старые `adm:form:*` JSON-обработчики сохранены для совместимости и технической диагностики,
но новые основные экраны на них не ссылаются. Там суммы остаются в копейках, проценты — в базисных пунктах.
Не используйте эти callback-ы как публичный API или способ обхода подтверждения.

## Изменения Phase 8

В главном меню видны «Мои VPN», «Создать VPN», баланс и пополнение.
В карточке пользователя кнопка корректировки баланса сразу выбирает пользователя.
Если начинать из общего меню, достаточно Telegram ID или @username — внутренний ID не нужен.
В карточке неопределённого платежа доступно восстановление по внешнему invoice ID.
Карточка сервера показывает доступность; OFFLINE исключается из автоматического выбора.
Обновление health не сбрасывает версию открытой административной формы.
Расширенные параметры реального inbound подключает инженер после получения конфигурации панели;
основные формы сохраняют эти параметры при обычном редактировании.
